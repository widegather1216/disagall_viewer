# Decisions (ADR) - Post Recommend

### [ADR-001] 본문 네이티브 버튼 `.click()` 위임 방식 채택
- **배경**: 디시인사이드는 추천 요청 시 비회원 토큰/식별자, 갤러리 ID, 게시글 번호, 로그인 세션 쿠키, 중복 추천 검증, 자체 alert 레이어 등 복잡한 내부 로직을 거침. 직접 Ajax `POST` 요청을 흉내내는 것은 토큰 파싱 실패나 DC 측 스크립트 변경 시 취약함.
- **결정**: 본문의 실제 추천 버튼(`button.btn_recom_up`)을 탐색하여 `.click()` 이벤트를 합성/트리거함.
- **영향**:
  - 디시 공식 추천 로직과 100% 동일하게 동작하며 사이드 이펙트가 전혀 없음.
  - 중복 추천 시 디시의 "이미 추천하였습니다" 처리도 자연스럽게 처리됨.

### [ADR-002] 추천 수 실시간 반영 및 옵저빙
- **배경**: 디시인사이드 추천 버튼 클릭 후 비동기 Ajax 응답이 도착하여 DOM의 추천 수(`<p class="up_num">`)가 갱신되기까지 수백 ms의 지연이 발생함.
- **결정**:
  - 클릭 즉시 버튼 펄스 효과와 함께 토스트 피드백 표시.
  - 400ms, 1200ms 주기로 추천 수 엘리먼트를 재조회하여 갱신된 최신 카운트를 뷰어 버튼에 즉시 동기화.
- **영향**: 사용자에게 즉각적인 시각 피드백을 제공하면서 정확한 최신 추천 수가 반영됨.

### [ADR-003] 추천 버튼 다중 선택자, 합성 이벤트 전파 및 연타 방지 가드
- **배경**:
  - 일부 마이너/미니 갤러리 및 모바일 환경에서 추천 버튼 태그가 `<a>` 또는 `<div role="button">`, `button[data-action="recommend"]` 등으로 구현되어 선택자를 놓칠 수 있음.
  - 단순 `btn.click()` 실행 시 브라우저 또는 디시 이벤트 리스너의 버블링 요구사항에 따라 무시되는 환경이 존재함.
  - 사용자가 단축키 `r`을 빠르게 연타할 경우 디시 서버에서 비정상 요청/중복 오류가 발생함.
- **결정**:
  - 선택자를 데스크톱/모바일/마이너/미니 갤러리 공통 14개 변종으로 대폭 확장.
  - 1차 네이티브 `.click()` + 2차 `dispatchEvent(new MouseEvent('click', ...))` 합성 마우스 이벤트 2중 디스패치 적용.
  - 1200ms 스로틀링 쿨다운 및 이미 투표된 게시글(`.on`, `.voted`, `disabled`) 사전 감지 토스트 안내.
  - 입력창(`input`, `textarea`, `isContentEditable`) 포커스 시 단축키 충돌 방지.
- **영향**: 모든 갤러리 환경에서 추천 버튼이 실패 없이 견고하게 동작하며 서버 중복 오류가 방지됨.

### [ADR-004] 갤러리 코드/비회원 추천 제한 환경 감지 및 실시간 카운트 증감 검증
- **배경**:
  - 마이너/미니 갤러리 설정 중 "비회원 추천 제한" 및 "도배방지 코드(`kcaptcha_use=Y`)"가 적용된 경우, 비로그인 상태(`is_login=N`)에서는 추천 버튼을 클릭해도 디시 서버에서 추천이 거부됨.
  - 기존에는 성공 여부와 무관하게 무조건 "추천을 눌렀습니다! 👍"라고 안내하여 사용자가 추천이 성공한 것으로 오인하는 문제가 발생함.
- **결정**:
  - `isUserLoggedIn()` 및 `isGalleryCodeEnforced()` DOM 판별식 구현.
  - 비로그인 유저 + 코드 적용 갤러리의 경우 뷰어 헤더 [개추] 버튼에 `🔒` 자물쇠 아이콘 및 툴팁 표시.
  - 추천 클릭 전 카운트(`beforeCount`)를 기억하고, 비동기 응답(1200ms) 후 카운트가 실제로 증가했는지 실시간 검증.
  - 카운트가 증가하지 않았고 비로그인 상태인 경우, `voted` 상태를 즉시 롤백하고 `"로그인이 필요한 갤러리입니다. (비회원 추천 제한 🔒)"` 명확한 토스트 피드백 표시.
### [ADR-005] 추천 이벤트 중복 디스패치 방지 (Single Dispatch 보장)
- **배경**:
  - ADR-003에서 `btn.click()` 직후 `dispatchEvent(new MouseEvent('click'))`를 순차 실행하는 2중 디스패치를 적용했음.
  - 이로 인해 `btn.click()`이 정상 동작하는 환경에서는 수 마이크로초 간격으로 동일한 클릭 이벤트가 2회 연속 발생하여 디시인사이드 내부 중복 방지 알림인 `"추천은 1일 1회만 가능합니다"` 팝업이 발생하는 부작용이 발견됨.
- **결정**:
  - `dispatchRecommendClick(btn)`에서 1차로 `btn.click()`을 시도하고 성공 시 즉시 `return true`로 종료.
  - 네이티브 `.click()`이 정의되어 있지 않거나 에러를 발생시키는 특수 환경에서만 `dispatchEvent`를 fallback으로 단일 실행하도록 변경.
- **영향**: 추천 버튼이 1회만 깨끗하게 호출되어 2회 중복 호출로 인한 "1일 1회" 경고가 완전히 해결됨.

### [ADR-006] 디시 기본 클래스 `btn_recom_up on` 오탐지 방지 및 세션 기반 투표 상태 관리
- **배경**:
  - 사용자가 추천을 누르지 않았는데도 "이미 개념글 추천을 완료한 게시글입니다" 토스트가 뜨며 클릭이 가로막히는 결함 발생. (뷰어를 끄고 웹페이지 버튼을 직접 누르면 정상 동작함).
  - 디시인사이드 데스크톱 실제 마크업(`<button type="button" class="btn_recom_up on">`) 분석 결과, 디시 데스크톱 본문의 추천 버튼에는 처음부터 기본 클래스로 `on`이 포함되어 있음.
  - 기존 로직에서 `btn.classList.contains('on')`을 "이미 추천함" 사전 조건으로 검사하여 미추천 상태의 글에서도 무조건 클릭이 차단되었음.
- **결정**:
  - 사전 `isAlreadyVoted` 검사에서 `btn.classList.contains('on')` 조건 제거.
  - 현재 글 세션 내에서 추천이 성공(`afterCount > beforeCount`)했을 때만 활성화되는 `hasVotedCurrentPost` 플래그 도입.
  - 뷰어가 열릴 때(`openViewer`) 아직 투표하지 않은 글인 경우 뷰어 버튼의 `.voted` 클래스를 자동 리셋.
- **영향**: 추천을 아직 누르지 않은 글에서 오판단으로 추천이 가로막히던 버그가 완벽히 해결됨.
